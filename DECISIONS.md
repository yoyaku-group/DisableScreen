# DECISIONS — DisableScreen → RunClosed

Décisions d'architecture. Un ADR = une décision. Nom RunClosed **provisoire** (package Swift + binaire CLI `runclosed` uniquement ; repo/bundle id inchangés jusqu'à G5).

| ADR | Décision | Raison / compromis |
|---|---|---|
| 001 | Swift pour le produit distribué ; Python conservé comme app quotidienne + snapshot d'audit. | Supprimer la dépendance Python externe et le pont de bundle. Migration incrémentale, pas big bang. |
| 002 | Noyau Swift (`RunClosedCore`) indépendant d'AppKit et des API macOS via protocoles injectables. | Tests déterministes (horloge, backends fakes) sans matériel. |
| 003 | Cible macOS 14+, Apple Silicon primaire ; Intel = compilé, non testé. Zéro dépendance externe (parsing CLI maison). | Limite la matrice ; pas de badge « supporté » sans essai. Le shell tourne sous Rosetta → tout build force `arch -arm64`. |
| 004 | Un seul propriétaire logique des demandes de maintien éveillé (lease). | UI et CLI ne doivent pas détenir d'états power contradictoires. |
| 005 | Modèle de propriété pour `pmset disablesleep` : on ne restaure que ce qu'on a posé, prouvé par `{prev, boot_uuid, set_at}` + readback. Sinon `conflict` → ne pas toucher. Jamais de `disablesleep 0` inconditionnel. | M6 est le seul effet root/global/persistant sans récupération (voir mutation-inventory). |
| 006 | Broadcast DDC/IOKit supprimé ; `brightness.external = softwareDim` (honnête), pas de faux DDC. | Aucun transport par-écran prouvé (A02, invariant 1). |
| 007 | `run --lid` refuse tant que le backend capot n'est pas qualifié (Phase 3, opt-in matériel). `run --idle-only` = premier wrapper réel sur API publique `IOPMAssertionCreateWithName`. | Une assertion idle publique ne couvre pas la fermeture du capot (S01). Pas de promesse non tenue. |
| 008 | Distribution directe signée/notarisée avant toute variante App Store. | Le Store exige des API publiques ; la notarisation ne transforme pas une API privée en publique. |
| 009 | **Un effet global/root n'est jamais muté sans baseline observable, et un état de récupération n'est jamais supprimé avant qu'un readback ne confirme le retour à l'état visé.** UNKNOWN ≠ OFF ; succès d'API ≠ succès observable. (Généralise ADR 005 aux 3 chemins : flag capot, écrans possédés, leases.) | Audit pré-merge PR #1 (2026-09-12) : 3 défauts recovery où un pré-état inconnu était traité comme OFF, où l'ownership était lâché avant readback, et où un écran non ré-activé perdait son id. La correction fait de l'observation (pas du rc d'API seul) la condition de tout write/delete d'état de récupération. |
| 010 | **Logique de présentation = cible pure sans AppKit**, testable sur Linux CI ; `AppDelegate` reste fin (fil de la vue, pas de la vérité). Le ViewModel + renderer vivent dans `RunClosedApp`, consommés par les UI natives futures (AppKit menu-bar en G2a, autres surfaces plus tard). | G2a (2026-09-14) : le `SnapshotBuilder.make()` doit rendre le tri-état `unknown` distinct de `off`, sinon la couche UI re-ment. La détection d'ambiguïté vit aussi dans le builder (défense en profondeur) car un futur backend (G2b) peut passer des snapshots pré-construits où le flag `DisplayInventory` n'est pas posé. Le test `testAmbiguousDisplayFlagged` est tombé sur cette vérité pendant l'écriture — c'est exactement la classe de garde-fou que le ViewModel pur permet. |
| 011 | **Toute surface cross-target vit dans un module dédié `RunClosedPersistence`**, pas dupliquée dans chaque consumer. Le path du fichier leases + la discipline d'écriture atomique sont l'apanage de `LeaseStore` (public). Les autres targets dépendent du module, ne ré-implémentent rien. | G2d prep (2026-09-14) : `LeaseStore` (target `runclosed`, lecture+écriture) et `LeaseReader` (target `RunClosedMenuBar`, lecture seule) dupliquaient la résolution de path `~/Library/Application Support/RunClosed/leases.json` et la logique `JSONDecoder + reap`. Avec G2b le nombre de consumers va croître (CLI write + menu-bar read + futur agent-adapter write) — la duplication deviendrait un bug en germination. Le module partagé expose 2 inits (canonique + URL-injectée pour tests) ; 5 tests cross-boot round-trip prouvent le contrat. Le CLI et la menu-bar dépendent maintenant du même module ; un changement de layout disque se fait à un seul endroit. |
| 012 | **G2b — display mutation en Swift via `DisplayMutator` protocol + `SLSDisplayMutator` (dlsym SkyLight) + `DisplayMutationPolicy` (pure, testable) + `DisplayMutationService` (orchestration) + `OwnedDisabledDisplays` (persistence) ; réactivation-on-launch re-écrit le record depuis l'OUTCOME, jamais depuis la map live (B3).** | G2b (2026-09-14) : port de la logique Python A04/B3 vers Swift pour fermer le chemin de mutation d'écrans. `SLSConfigureDisplayEnabled` est une API privée SkyLight — wrappée via `dlsym` au load du module (même chemin que le Python via ctypes), pas d'entitlements ni de signature spéciale. Le protocol `DisplayMutator` permet aux tests d'injecter un fake sans toucher le vrai backend ; les invariants ADR 009 (UNKNOWN≠OFF, readback, retain-failed-IDs) sont préservés. 4 fichiers ajoutés : `DisplayMutationPolicy.swift` (Core), `DisplayMutation.swift` (MacSystem), `DisplayMutationService.swift` (MacSystem), `OwnedDisabledDisplays.swift` (Persistence). CLI : `runclosed disable <id>` / `enable <id>` / `restore --owned`. Live verify sur 1 écran : `disable 1` refusé exit 3 (last-active guard) ; `enable 1` exit 5 (kCGErrorCannotComplete sur 1 écran — backend refuse le no-op). 21 nouveaux tests verts (6 policy + 9 service + 6 persistence). |
| 013 | **G2c — `pmset disablesleep` mutation en Swift via `LidMutationPolicy` (pure, refuse UNKNOWN B1 + no-op) + `LidAssertion` protocol + `PMSetLidAssertion` (subprocess wrapper) + `LidMutationService` (orchestration : set gate sur prior observable, ownership claim sur readback verified) + `OwnedLidAssertion` (persistence atomique).** Architecture pmset subprocess fork+exec : (a) exit code non-fiable (`pmset` retourne 0 même quand le flag n'est pas réellement muté — ex. appel non-root), (b) `pmset` redirige ses warnings stderr → stdout quand stderr ≠ tty. Lecture pmset -g = authoritatif (B2 invariant). | G2c (2026-09-14) : port de la logique Python `_set_lid_stay_awake` (B1 + B2) vers Swift. 5 fichiers : `LidMutationPolicy.swift` + `LidMutationError.swift` (Core), `LidAssertion.swift` + `LidMutationService.swift` (MacSystem), `OwnedLidAssertion.swift` (Persistence). CLI : `runclosed lid-stay-awake on|off|status`. Live verify (machine Ben, non-root) : `on` → exit 5 avec message actionable `'/usr/bin/pmset' must be run as root... | readback: observed=false, expected=true` — la B2 a honnêtement refusé (pas de fausse réclamation ownership). **Live mutation réelle nécessite élévation** (relie backlog A14). |
| 014 | **G2b-corrections — fix pré-merge de 3 défauts découverts en review externe.** (1) `SLSDisplayMutator.setEnabled` retournait `action: enabled ? .deactivate : .deactivate` — typo qui masquait l'opération dans tous les `OperationResult` (logs/diagnostics/agents futurs mentaient sur enable vs disable). Corrigé via nouveau case `.activate` dans `DisplayAction` (Core, à côté de `.deactivate`), 5 sites corrigés. (2) `cmdRestoreOwned` retournait `exit 0` même sur restauration partielle (stillOwned non vide) — pour un caller automatisé (agent G4, script CI) `exit 0 = succès = retry zappé`, ce qui est un échec opérationnel silencieux. Corrigé : `return stillOwned.isEmpty ? 0 : 5` (cohérent avec exit 5 = backend failure dans le même CLI). (3) `PROGRESS.md §G3` annonçait `restore --owned = stub` après que G2b l'a implémenté — drift documentaire qui aurait trompé une session Claude post-compact. Corrigé : §G3 référence §G2b-corrections, `restore --owned` = G2b live, `restore --lid` reste G3 stub. | Phase 1 (2026-09-15) : review externe a identifié les 3 défauts avant merge PR #2. (1) `DisplayAction` étendu (`Models.swift:24`) avec `.activate` + docstring du typo originel. (2) `cmdRestoreOwned` (`main.swift:255-273`) : `stillOwned.isEmpty ? 0 : 5` + docstring du contrat. (3) `PROGRESS.md §G3` ligne 84 mise à jour. **4 nouveaux tests verts** : `testDisablePropagatesDeactivateAction`, `testEnablePropagatesActivateAction`, `testRestoreOwnedPropagatesActivateAction`, `testRestoreOwnedReturnsNonEmptyListOnPartial` (qui pin le contrat service-level que le CLI dépend). Suite globale **72/72 verts** (était 68/68). Build 0 warning. Le `FakeDisplayMutator` produit maintenant `action = enabled ? .activate : .deactivate` (miroir du vrai backend post-fix). |
| 015 | **BOOT CHANGE ≠ PROOF OF RESTORATION — le record d'ownership lid n'est JAMAIS supprimé uniquement parce que `bootID` a changé.** `OwnedLidAssertion.load()` retourne le record verbatim ; la réconciliation vit dans `LidMutationService.reconcileCrossBoot()` fondée sur l'OBSERVATION (`pmset -g`) : stale + observé OFF → purge autorisée (seul chemin d'effacement) · stale + observé ON → conservé en `recoveryPending` (pas d'auto-mutation) · stale + UNKNOWN → conservé (UNKNOWN ≠ OFF). Un record stale ne confère PAS d'ownership sur le nouveau boot (`setEnabled(false)` refuse `notOwned`). Le reboot-comportement de `disablesleep` est UNDOCUMENTED — le test physique (Phase 4, opérateur présent) documentera le comportement observé, mais le modèle fail-closed doit être correct DANS LES DEUX CAS. | Review externe (Ben, 2026-09-15/16) : le cross-boot discard silencieux d'origine (hérité par analogie avec `OwnedDisabledDisplays` G2b) encodait « le reboot restaure le flag » comme vérité alors que le comportement est undocumented et contradictoire dans les sources publiques. `display ≠ disablesleep` : un écran possédé est un effet local visible ; le flag est global et invisible. 6 nouveaux tests verrouillent le contrat (purge-after-observation, recoveryPending ON, recoveryPending UNKNOWN, no-op même boot, status flag, pas de OFF gratuit avec record stale). Remplace `testStaleBootRecordIsDiscarded`. |

INTERDIT et absent du code : exec générique, shell, command string, path/args arbitraires, sudo, tout autre réglage pmset.** L'app garde son readback indépendant `pmset -g` comme vérité autoritaire après toute réponse XPC (ADR 009 inchangée). | A14 tranche 1 (2026-09-16) : `RunClosedHelperSupport` (`RunClosedHelperDescriptor` + `DaemonStatus` + `DaemonRegistrar` protocol + `SMAppServiceDaemonRegistrar` + `HelperLifecycleService` avec `Report` honest — `xpcImplemented:false` en clair) + `RunClosedHelper` daemon executable (start/log/SIGTERM, aucun privileged op) + plist `Resources/com.benjaminbelaga.runclosed.helper.plist` (SANS MachServices volontairement — aucune surface privilégiée atteignable pendant la qualification registration). 6 tests FakeRegistrar (requiresApproval surfacé, notFound ≠ notRegistered, register seulement depuis notRegistered, chemin normal → requiresApproval, report honest bounded-op + no-XPC, identités descriptor stables). **31/31 verts sur la branche.** NOT_TESTED (live) : registration réelle (nécessite app bundle signée Apple Development/Distribution — identités présentes sur la machine — + geste utilisateur Login Items), XPC, setDisableSleep live. |

Plist T1 sans `RunAtLoad`/`KeepAlive`/`MachServices` : aucun trigger, aucun listener → le daemon ne tourne jamais tant que T2 n'ajoute pas `MachServices`. Signing : `SIGN_IDENTITY` (défaut ad-hoc ; registration live = Developer ID). | Deep review 2026-09-17 : l'ADR 016 shippait un plist `Program` absolu `/Library/LaunchDaemons/...` (layout SMJobBless) — contraire à la spec Apple « replace the Program key with the BundleProgram key and make the path relative to the bundle » — et aucun script d'assemblage n'existait. Correctifs : plist `BundleProgram` + contradiction `KeepAlive` retirée ; script d'assemblage + `codesign --verify --strict` ; `openLoginItemsSettings()` exposé + CLI `runclosed helper status/register/login-items/unregister` ; régression unitaire plist ↔ descriptor. | 018 | **SMAppService daemon — sémantique macOS 26 MESURÉE : état frais = `notFound` (pas `notRegistered`) ; le premier `register()` peut THROW `SMAppServiceErrorDomain code 1` ("Operation not permitted") tout en transitionnant vers `requiresApproval` ; `unregister()` → `notRegistered`.** Codé en conséquence : `registerAndReport()` tente la registration depuis `notRegistered` ET `notFound` (sinon une machine fraîche ne registrerait jamais) ; `register()` du registrar traite pending/enabled comme succès malgré le throw ; pending n'est jamais re-registré (pas de boucle). | E2E réel 2026-09-17 (macOS 26.6, .app Developer ID installé /Applications) : cycle complet status→register→requiresApproval→unregister→notRegistered. Sans ce codage : (a) refus de registrer depuis `notFound`, (b) faux échec rapporté sur `register`. Le couple throw+pending est le chemin NORMAL — l'approbation utilisateur est le gate. |

## Décisions de périmètre (cette tranche G0–G2)

- Même repo, branche de mission `agent/claude/20260911/…` (worktree lié via `yy mission`). Register forcé (`--force-capacity`) : `--headless` n'exécute aucun harness, coût CPU nul ; charge due aux sessions voisines.
- Tests matériels (capot, écran externe MB16AH) derrière `RUNCLOSED_HW_OPTIN=1`, exécution seulement avec Ben présent. Un seul écran (XDR intégré) branché → externe = `BLOCKED_HARDWARE`.
- Aucun backend capot privé (`coke`) exploré ici (décision post-qualification).

## Décision d'organisation du code Swift (post-G2a)

- **Nouveau target `RunClosedPersistence`** (lib, dépend uniquement de `RunClosedCore`) absorbe toute la persistance on-disk des leases. `LeaseStore` y vit en `public` avec un init canonique (path Application Support) + un init URL-injecté pour les tests.
- `runclosed` et `RunClosedMenuBar` déclarent une dépendance sur `RunClosedPersistence` ; aucun des deux ne contient plus son propre code de persistence. La duplication qui existait depuis G2a (10–30 lignes × 2 targets) est supprimée ; un futur G2b / adaptateur agent (G4) consomme la même surface sans la re-créer.
- Les deux anciens fichiers locaux (`Sources/runclosed/LeaseStore.swift`, `Sources/RunClosedMenuBar/LeaseReader.swift`) sont supprimés — le canonique est dans `Sources/RunClosedPersistence/LeaseStore.swift`.
